# 开源面试工具（视频会议 + 现场写代码）分析

> 这一步是「面试工具」调研：本质是**实时视频/音频会议 + 面向技术面试的附加能力（现场写代码、共享编辑器、在线执行、记事本）**。
> 复用目的：若我们的 AI 模拟面试官需要"视频通话 + 在线写代码"场景，可借用这里的媒体层与协作编辑器实现。

四个已拉取仓库逐一实读（README + package.json/pyproject + 主要源码），另有两个仅 web/README 参考（TalentIQ、CollabCode）。

---

## 一、逐仓库分析

### Repo: Interview4Me（Int4Me）
- **是什么**：全栈 mock 面试平台——1对1 WebRTC 音视频 + Monaco 协作代码编辑器 + Piston 多语言在线执行 + 共享 notepad，一个房间内完成。
- **技术栈**：React18+Vite+Tailwind；Node+Express+Socket.IO+MongoDB；媒体用 **PeerJS**(WebRTC,默认公共云 broker,无 TURN)；编辑器 **Monaco**(但整文经 Socket.IO 广播,无 CRDT)；执行**客户端直连公共 Piston**。
- **闭环**：登录(JWT) → 面试官 Start(房间=自己peerId) → 候选输房间号加入 → call 直拨建视频 → 编辑器/输出/notepad 经 Socket.IO 房间广播 → Run 调 Piston 执行并广播。
- **部署/成本**：无 Docker；后端需 MongoDB(2 env)，前端 Vercel；无云端付费(PeerJS 公共 broker 免费)。
- **亮点**：闭环完整、代码量小易读、Piston 客户端封装干净、P2P 秒级可用。
- **不足/坑**：编辑器整文广播==last-writer-wins 会互相覆盖；无 TURN 易黑屏；**密码明文存 Mongo**；CORS 硬编码线上域名(本地要改代码)；一个 socket.off 事件名拼错。
- **可复用**：`Output.jsx`(Piston 封装)、`AudioVideoScreen.jsx`(PeerJS 呼叫/双流范式)、`constants.js`(6 语言+版本表)、`server.js`(7 事件房间中继)。

### Repo: interview_platform1
- **是什么**：1对1 视频聊天室(手动 WebRTC) + 基于 **Yjs+y-webrtc** 的 p2p 协作代码编辑 + Piston 执行（挑战赛作品）。
- **技术栈**：React18+Chakra+Vite；Node+**纯 Socket.IO 信令**(约45行)；媒体**原生 RTCPeerConnection**；编辑器 **Monaco+Yjs+y-webrtc(WebRTC DataChannel,不经服务器)**；执行 axios 调公共 Piston。
- **闭环**：email+房间号 → 服务器 email↔socketId 双映射 → 先到者 Call 发 offer、后者自动 answer → addTrack 推流、negotiationneeded 重协商 → 编辑器经 y-webrtc 实时同步 → Run 调 Piston,输出进 SyncedStore 共享数组。
- **架构要点**：信令极简且正确(offer/answer/nego 纯中继)；**文档同步是真正的 CRDT(Yjs+y-webrtc,服务器不碰内容、不持久化)**；**但 y-webrtc 房间名写死 "test-room"/"output_room"**（所有用户共享同一文档,房间号只约束视频信令）——明显 demo 级 hack；远端渲染有 JSX bug。
- **部署/成本**：后端 Render(前端硬编码 onrender URL)，前端 Vite；无 Docker、无鉴权、无持久化。
- **亮点**：手动 WebRTC 信令流程是全仓库最干净可控的参考；Yjs+y-webrtc 是编辑同步的正确姿势；SyncedStore 同步输出是精巧设计。
- **不足**：y-webrtc 房间名写死(必须改成按 roomId 生成)；无 TURN；无持久化；远端视频 JSX bug；无鉴权。
- **可复用**：`backend/index.js`(45行 WebRTC 信令中继可直抄)、`services/peer.js`(RTCPeerConnection 单例封装,补 TURN 即生产可用)、`codeeditor/CodeEditor.jsx`(Yjs+MonacoBinding 接线范式)、`store.js`+`Output.jsx`(SyncedStore 共享数组)。

### Repo: live-code-interviewer
- **是什么**：**生产化程度最高**的 live 技术面试工具——SuperViz 视频会议 + 同步 Monaco 编辑 + Piston 执行 + Firestore 存代码 + 录制/转写/AI 报告全自动。
- **技术栈**：React18+TS+Vite+Chakra(纯前端,无自建后端)；全部 SaaS——**SuperViz**(视频+Yjs协作+录制+转写)、Firebase Firestore(版本化存码)、Piston(执行)。
- **闭环**：输入用户名+房间 → SuperViz 房间包裹编辑器+视频 → Yjs 实时同步 → Save Code 写 Firestore `codes/{roomId}/versions/{n}` → 全程录制 → 结束拿报告链接 `/interviewReport/?roomId=x` → 报告页经 SuperViz REST 拉转写/摘要/主题/问题/行动项。
- **架构要点**：一切媒体/协作/录制挂 SuperViz，零自托管；报告是独立第二个 Vite 入口；转写是异步任务(提示"最长20分钟")；Firebase Hosting + GitHub Actions 部署。
- **部署/成本**：Firebase Hosting+CI；需 SuperViz 双 key+client_secret+security key+Firebase key。成本取决于 SuperViz 订阅(录制/转写/AI 报告是付费能力)。无 Docker、无自建后端。
- **亮点**：**录制→转写→AI 报告闭环与"AI mock interview"产品最互补**；报告页结构、按 roomId 分享、Firestore 版本化存码都是可借鉴产品范式；TS+Chakra 代码质量较好。
- **不足**：对 SuperViz **全栈锁定**(媒体、协作、录制、转写、AI 分析全 proprietary,换供应商=重写)；报告 AI 是黑盒,无法控制模型/提示词；无鉴权；转写延迟大。
- **可复用**：`api.ts`+`Output.tsx`(Piston 封装)、`CodeEditor.tsx`(Yjs+MonacoBinding+provider 注入,换自建 provider 即脱离 SuperViz)、saveCode(Firestore 版本化存码模式)、`services/getRecording.ts` 等(第三方录制/转写 REST 范式)、`interviewReport/`(独立分享式报告页结构)。

### Repo: livecoding
- **是什么**：极简协作代码编辑器,故意**没有**视频、执行、鉴权、聊天——只有多人同步编辑 + 语法高亮。
- **技术栈**：Vue3(无 SFC, esbuild 单 bundle) + CodeMirror 6 + vue-router；Python3.12+FastAPI+websockets+typer+Poetry；同步**原生 WebSocket**；**从零手写 CRDT(RGA)**(服务端 Python 与客户端 JS 各一份)。
- **闭环**：创建房间(14位谐音 ID) → 分享 `/room/{id}.{ext}` → 客户端拉全量事件日志+offset 建 WS → 输入名字进入编辑 → insert/delete 事件发服务端,服务端应用并广播 → 光标以 gid 锚定、60ms 节流、不入日志 → 服务端每10s 物化文本 gzip 落盘、事件日志超阈值 compaction、30天 TTL。
- **架构要点**：服务端是权威事件日志+CRDT 副本,客户端跑同一算法；(counter,siteId) 全局有序、删除用 tombstone；`ValidationError`==分叉→直接断开让客户端整页重载；文档限25k字符、单 worker(内存态)。部署 VPS+systemd+nginx+Let's Encrypt。
- **部署/成本**：无 Docker,`make run`(esbuild+uvicorn:5000)；纯自托管,无付费。
- **亮点**：极干净的教学级 CRDT,双端带测试；gid 锚定光标+节流+心跳+compaction+持久化,工程细节教科书级；README 解释每个取舍。
- **不足**：无视频/音频/执行/鉴权,只能当编辑器组件；手写 CRDT 换 Yjs 是重写；Vue 无 SFC 写法维护成本高；无 Docker、单 worker。
- **可复用**：`domain/document.py`+`frontend/lib/document.js`(双端 CRDT 权威参考,建议用 Yjs 替代而非直接搬)、`domain/room.py`(房间/事件日志/持久化/compaction 生命周期)、`frontend/room.js`(gid→offset 光标渲染、pending cursor、心跳、只读降级)。

### （web 参考）TalentIQ-Interview
- **是什么**："Google Meet + LeetCode + VS Code" 三位一体；视频会议 + 实时代码协作 + 在线执行 + 屏幕共享。
- **技术栈**：React18+Node18+MongoDB6+Stream(视频/聊天)。
- **不足**：依赖 Stream 第三方视频服务。

### （web 参考）CollabCode / OpenCollab
- **是什么**：生产级协作代码编辑器(技术面试/结对编程),多语言 + 在线执行 + Firebase 实时数据库。
- **技术栈**：Node>=16 + Firebase(realtime DB) + Vercel 部署。

## 二、跨项目横向观察（如何为 AI mock-interview 产品"加视频+写代码"）

**媒体层**：复用 `interview_platform1` 的**原生 RTCPeerConnection + Socket.IO 信令**(45行、完全自托管、随时可补 TURN)是最可控的视频层；想省事用 PeerJS(Interview4Me)但要摆脱默认公共 broker 并自建 PeerJS server；规模大/多人再考虑 LiveKit/SuperViz。live-code-interviewer 的 SuperViz 全托管最省力但锁定最重。

**编辑器同步层**：**Yjs + MonacoBinding 是事实标准**(interview_platform1 的 CodeEditor.jsx 接线 + live-code-interviewer 的 provider 注入两种写法)；配合自建 y-webrtc 或 Socket.IO 中继。**Interview4Me 的整文 Socket.IO 广播是应避免的反模式**(并发编辑互相覆盖)。

**执行层**：三个带执行的仓库**全部直连公共 Piston**(emkc.org),无一自建沙箱——客户端封装约20行可照抄(Output.jsx/api.ts),生产化再自托管 Piston。

**产品增量**：live-code-interviewer 的"录制→转写→AI 报告 + 版本化存码 + 独立报告页"是最值得借鉴的产品闭环(换掉 SuperViz 依赖后架构可平移,与我们"复盘"卖点天然契合)。

**过度设计清单**：livecoding 的手写 CRDT(教学价值高但对产品是重复造轮子,Yjs 已覆盖)；Interview4Me 装了 tldraw/draft-js/react-whiteboard-pdf 等一堆未用依赖；interview_platform1 把 simple-peer/fast-diff 装进依赖却没用到；live-code-interviewer 拆了 9 个 reportGet* 单函数文件却全打在 SuperViz 私有 API 上,脱离即废。

> 事实核查：Interview4Me 密码明文存 Mongo、interview_platform1 的 y-webrtc 房间名写死、live-code-interviewer 纯 SaaS 无后端、livecoding 无媒体无执行——以上均来自实读源码,非 README 宣传。
