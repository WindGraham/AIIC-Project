# AI 模拟面试方案 · 市场与形式总览

> 调研日期：2026-08-30。目的：先弄清「现在市面/开源都怎么做」，再决定我们做什么。
> 关键结论：**形式（形态）决定技术复杂度与差异化上限；多数产品停在"AI 问答"，真正能形成训练价值闭环的是少数。**

## 一、交互形式（形态）光谱

| 形态 | 技术复杂度 | 拟真感 | 说明 | 典型代表 |
|------|-----------|--------|------|---------|
| **纯文字 chat** | 低 | 低 | 最快跑通，但反馈价值取决于 prompt 与复盘逻辑 | HopeLoom/AI-Interview、NextStep.AI、interview-skills |
| **文字 + 结构化复盘/评分** | 中 | 中 | 文字之上叠加"逐题评分、雷达图、薄弱点分析"才有训练价值 | MockMate（岗位画像+逐题回顾+雷达图） |
| **语音（ASR+TTS）** | 中高 | 高 | 最接近真人；需要 STT/TTS 与流式/双工处理 | offerMaster、DeepInterview、assess-AI、grillkit、Seekr、ai-interviewer |
| **视频通话模拟（WebRTC）** | 高 | 高 | 浏览器视频通话 UI + 语音 AI 面试官 | Ai-Video-Interviewer |
| **数字人/虚拟形象** | 很高 | 高 | 3D/Live2D 形象 + 表情/口型同步 | AI-agent-Avatar-Interview-Assistant、socratic_mirror |
| **视频+现场写代码（面试工具）** | 高 | — | 属"面试工具"而非"模拟面试官"，用于真人面试撮合/考核 | Interview4Me、TalentIQ、CodeInterview、CoderPad |

**用户研究（docs/调研记录.md）的结论**：理想排序 视频(带形象) > 语音 > 文本；但说明书中「文字做扎实是基础线，语音/视频是加分项，不是必选项」。

## 二、商业/产品层面的三类形态（B 端选型视角，北森文）

1. **一体化 AI Agent 平台**：企业 HR SaaS，自研人才科学大模型（如北森 SenGPT），全链路（面试评估回流人才库、黑名单风控、心理测评），人机一致性 0.89-0.95。面向**企业招聘筛选**。
2. **题库社区型产品**：题库 + 外挂 AI 面试模块，主要为技术岗校招。面向**候选人刷题 + 企业筛人**。
3. **独立 SaaS 工具**：单一场景、调用通用大模型 API。面向**候选人自练**。

> 对我们的启示：**我们要做的是「候选人自练」侧的第 3 类，但要做出差异化**——不要让用户觉得"还不如直接用 ChatGPT"。

## 三、B2C 求职侧的代表产品（商业）

- **Final Round AI / Interview Coder**：面试"外挂"式实时辅助（面试时给提示/回答），主打"面试中 AI 帮答"，争议大；也有 mock 练习。
- **Natively AI**：模拟面试，需自行搭建/DIY。
- **MockIF / Qwyse / PrepTalk 等**：各类 mock 平台对比。
- 共同点：多数在"题目生成 + 反馈报告"上迭代，**少有真正还原"面试官会追问/打断/压力面"的拟真交互**。

## 四、支撑层技术选型（决定我们能多快做出来）

- **语音 Agent 框架三选一**：LiveKit（开源，自托管实时音频，生态最全）、VAPI（托管，快但贵/不透明）、Pipecat（开源 Python 实时框架）。**自托管 livekit + 自选 ASR/TTS 更可控、更贴合"低成本"诉求**。
- **ASR**：本地 faster-whisper（免费、离线、零成本；中文准确率一般、需录完才转写）vs 火山/豆包流式 ASR（中文更准、边说边出字、按小时计费）。
- **TTS**：Edge-TTS（免费）vs 豆包 Seed-TTS（更自然、有情感）vs OpenAI。
- **LLM**：OpenAI 兼容协议（DeepSeek 便宜好用 / Kimi / Qwen / 火山），成本 ¥0.3/场左右。
- **复用价值排序**：Voice/ASR/TTS 层与"评分+复盘"逻辑最值得借鉴；纯前端 UI 价值低。

## 五、对 16 小时 MVP 的直接影响

- **语音能做，但要做薄**：把「文字闭环（出题+追问+评分+复盘）」做扎实，语音作为薄薄一层（ASR 收转写、TTS 出声）叠加，而不是让语音成为核心难点。
- **真正差异化的三个抓手**（来自调研 + 现有产品空白）：
  1. **岗位人才画像**（JD + 真实在岗者画像 → 告诉用户该表现哪些侧重点）——现有开源几乎都停留在"出题"，画像分析几乎空白（MockMate 有雏形）。
  2. **拟真追问/打断/压力面**（还原面试官的"深挖"与"打断"，让用户 get 到面试官意思）——现有多数是"一问一答"套路。
  3. **可执行复盘**（逐题评分 + 判定答得好/不好 + 标准答题框架 + 薄弱点雷达图）——做到"比直接用 ChatGPT 更结构化"。
