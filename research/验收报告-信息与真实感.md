## 一、任务一：谁获取的"信息"最多？用什么方式？

### 我的独立结论（按维度拆分，不给出单一"总冠军"）

**维度 A（外部岗位/公司信息，运行时获取）→ MockMate 第一，且是唯一默认运行时联网抓取者。**

证据（`MockMate/backend/web_research.py`）：
- 三引擎运行时抓取：`SEARCH_ENGINES` 配置 360/bing/baidu 三家（`web_research.py:70-98`），`_search_with_fallback`（:250）逐个引擎降级、公司命中过滤（`_results_relevant`:260）。
- 查询模板覆盖岗位 JD / 面经 / 公司定向：`SEARCH_SOURCES`（:24-47）含 `{company} {position} 招聘 岗位职责 薪资待遇`、`{company} {position} 面经` 等；AI 扩展岗位同义词（`_expand_position_synonyms`:162）扩大召回。
- 结构化产物：岗位画像 JSON 强制字段 `hiring_status / salary_range / company_insights / sources` 等（`_build_profile_prompt`:379-401），公司定向信息优先且无数据时明确标注"未查到该公司专属信息，不要编造"（:363-364）。
- 注入后续：出题（`mock_interview/mock_engine.py:220,288` 岗位画像 JSON 进问题 prompt；`interview_engine.py:380-403` required_skills/tech_stack 为核心考察范围）、评分（`main.py:888` `context={"profile": session["profile"]...}` → `interview_engine.py:843` 评估 prompt 含"岗位信息: {profile}"）、总结报告（`interview_engine.py:465-467` `end_interview` 带 profile）。
- 入站接口：`main.py:711-730` `research_position`。

对比（运行时联网维度）：
- DeepInterview 的公司研究需 Tavily key 才真联网，默认是罐装假结果：`core/adapters/search.py:59-70`（`search_provider` 默认 "mock"）→ `core/adapters/mock.py:107-121` 返回 "Deterministic mock snippet"。知识库同理默认 `MockKnowledge`（`core/adapters/knowledge.py:133-139`）。
- AI-agent-Avatar-Interview-Assistant 用 Perplexity API 做公司研究（`Backend/app/services/.../company_research_agent.py:15-18`，子代理核验），是第二家真运行时联网的，但产出结构简单（存 Cosmos talent 表），注入出题的深度与 MockMate 不可比。

**维度 B（总渠道数量 × 候选人/岗位建模深度）→ DeepInterview 第一（typed InterviewContext），CV 解析深度全场最高。**

证据（`DeepInterview/apps/agent/src/deepinterview_agent/`）：
- prep 图并行扇出：CV / JD / 公司研究 三路并行 → gap → 出题计划（`prep/graph.py:46-57`）。
- CV 真实文档解析（PDF/DOCX → markitdown，扫描件 Gemini 兜底）：`prep/cv_extract.py`（316 行）、`prep/nodes.py:73-96`；产出结构化 `CandidateProfile`（项目/教育/成就/技能/120 字摘要，`shared_models.py:54-66`）。
- JD → `JobSpec`（must_have/nice_to_have/tech_stack，:72-82）；公司研究 → `CompanyIntel`（values/interview_process/recent_news + citations，:95-104）；gap → `GapAnalysis`（probe_targets/missing_skills，:110-117）；全部装进 `InterviewContext`（candidate/job/company/gap/plan/cursor/answers/scorecard，:254-264）。
- 渠道清单：简历 + JD + 公司研究 + skill 题库包（`skills/` 30+ 份 playbook：round structure/question bank/signals/pitfalls + confidence/version/source_runs 元数据）+ LightRAG 知识侧车（`api/kb.py` ingest/query + `core/adapters/knowledge.py`）+ 真实语音转录（`worker.py` `wire_transcript_capture`:87-114，`conversation_item_added` 抓 STT 与 agent 发言）+ 逐题评分（`post/evaluator.py`，rubric+target_competency）。
- 题库包注入出题：`prep/nodes.py:232-263` `_skill_library_hint`（检索公司×岗位×级别 playbook 注入 question_planner）。

**维度 B2（候选人信息：解析深度 / 回答挖掘 / 简历锚定防泛化）**
- 解析深度：DeepInterview 最高（PDF/DOCX 文档解析 + OCR 兜底 → 结构化 CandidateProfile：项目/教育/成就/技能，`prep/cv_extract.py`）；其次 InterviewPal（pypdf + LLM 结构化，`InterviewPal/backend/app/utils/pdf_to_text.py:4-13`）、AI-Interview（`parse_resume` → LLM 画像，`service.py:857-877`）、ai-mock-interview（LLM 读粘贴文本，`api/resume/route.ts:83-103`）。MockMate/offerMaster 只是原文截断进 prompt（`mock_engine.py:219` 3000 字；`nodes.py:33` 6000 字），无结构化。
- 回答挖掘与记忆：DeepInterview（真实 STT 转录逐轮入账 + 题目游标 + 超时恢复答案 `state.py:146-201` + 词数自适应难度 `state.py:237-323`）；offerMaster（跨题历史 + 矛盾必追问 + 评分引用原话 `prompts.py:94,197-199`）；MockMate（全历史 + 已覆盖考察点 + 追问必引用 `mock_engine.py:202-269`）；AI-Interview（逐轮 topic/subtopic 对话历史追踪，`master_agent/interview_topic_tracker`）。
- 简历锚定防泛化：NextStep.AI 最明确——每个示例回答必须带 `experience_name` + `experience_source_quote`（简历原话）+ `confidence` 三档（`utils/prep_generator.py:79-84`）；offerMaster/DeepInterview 通过"简历+JD 进出题"间接锚定。

**维度 C（跨场学习/积累）→ 领先者与先行结论不同：warmscreen 是最"自动"的统计学习；DeepInterview 是最"结构化"的半自动学习；MockMate 有 QLoRA 微调管线。**

- warmscreen：`packages/agents/src/reflexion/learning.ts` — 每次面试后自动更新题目指标（timesAsked/avgScore/correlationScore，:59-85, 238-288）、自动按相关性精修评分模型权重并新建版本（`refineScoringModel`:90-199）。这是全仓唯一"无需人工介入"的跨场学习。
- DeepInterview：`skilllib/distiller.py` `propose_skill`（从已评分面试提炼题库/信号/pitfalls/rubric 校准草稿，去 PII，写入 `_review/`）+ `skilllib/promote.py`（合并去重、confidence+0.1 封顶、source_runs 累加）——真实积累，但 promote 必须人工/LLM 审核（`promote.py:1-12` 明确 "NEVER called automatically"）。
- MockMate：`finetune/collector.py`（评分记录 + 用户点赞/点踩 → 训练数据）+ `finetune/train.py`（QLoRA 微调 Qwen）——真实管线，需手动触发。
- intervio：跨会话记忆蒸馏（`backend/app/memory/distillation.py` LLM 抽取持久事实 + 时间衰减检索）——是"记忆积累"不是"模型学习"，但也是真实现象。
- 先行结论未提以上三者；offerMaster / AI-Interview / NextStep.AI / 其余仓库均无跨场学习。

**其他仓库的信息形态（供对照）：**
- NextStep.AI：`utils/prep_generator.py` — 纯 LLM 生成 prep 报告，简历锚定（`experience_source_quote` 必须引用简历原文 + confidence 三档，:79-84），公司情报（know_all_about_them）完全靠 LLM 内部知识、无任何联网（:97-102）；失败走硬编码模板（`_local_fallback`:396）。是"报告产物"，不是面试循环。
- interview-skills：`references/*.md`（jd-parser.md / resume-parser.md / company-profiles.md 阿里腾讯字节 Google Meta Amazon 等大厂画像）——静态方法论/知识包，非运行时收集。
- AI-Interview：`backend/interview_configuration/service.py` — JD（文本/PDF）→ JobDetails（:487-566）、简历解析 → 候选人画像（:857-877）、模板+例题+starter code（:802-826）、多 panelist 背景/人格/头像生成（:568-679）；无运行时联网。
- offerMaster：简历+JD 原文进 LLM 出题（`backend/app/agent/nodes.py:18-39`），无联网、无结构化解析。

**一句话结论（任务一）：**
- 若"信息"= 运行时获取的外部岗位/公司情报 → **MockMate 最多**（三引擎默认联网、公司定向、结构化画像、注入出题+评分+报告）。
- 若"信息"= 渠道数量 × 结构化建模深度 → **DeepInterview 最多**（CV 解析最深、typed InterviewContext、skill 题库包 RAG、知识侧车、真实转录/评分闭环），但要注明其联网类渠道默认是 mock、需外部配置才真正生效。
- "跨场积累"维度不能漏：warmscreen（自动统计+评分模型精修）、DeepInterview（skill library，半自动）、MockMate（QLoRA，手动）三家才有，其余没有。

## 二、任务二：谁最像真实面试？

### 逐维度事实

**1) 全双工实时语音 / 可打断**
- 真全双工（LiveKit agent / OpenAI Realtime / Gemini Live）：**DeepInterview**（`live/interviewer.py` Agent + `worker.py`：Silero VAD、deepgram STT、turn_detection `MultilingualModel`、`interruption min_words=3`，`worker.py:486-514`；可打断有 3 词门槛）；**Assess-AI**（`agent/agent.py:635-650`：silero VAD + deepgram STT + groq LLM + deepgram TTS 的 AgentSession）；**interview-ai-assistant**（`interview_agent.py:41-57`：deepgram/openai/cartesia + MultilingualModel，`allow_interruptions=True`）；**InterviewPal**（前端直连 OpenAI Realtime，`interrupt_response: true`——但后端 evaluation 全是空文件，产品未完成）；**socratic_mirror**（`backend/live_session.py` Gemini Live 双向音频 WebSocket，协议含 `interrupted` 事件）。
- 部分双工/回合制：ai-interviewer（aiortc 真 WebRTC 但 1s 缓冲+2s 静音才触发，无 barge-in）；AI-Interview（WS 音频流 + 播放完成驱动回合，无显式打断消息）；ai_mock_interview（全双工托管在 VAPI 平台，仓库内无自研流式代码且 `/api/vapi/generate` 无调用方，链路断）。
- 非全双工（push-to-talk / 录制-回放）：MockMate（前端 `InterviewView.vue:378-393` Web Speech API push-to-talk + 流式 TTS；`mock_state.py:446-451` 的"打断"是文本级概率切换面试官，非音频 barge-in）；offerMaster（`api/interviews.py:3` 明确 "turn-based"，音频 Blob 上传 STT + TTS mp3 由 `<audio>` 播放，`frontend/lib/api.ts:68`）；grillkit（push-to-talk 录音 `{"type":"stop"}` 一次性返回 + Piper 单向题目音频）；warmscreen（`voice-interviewer.ts` TTS 返回 MP3 Buffer，无 agent 入房说话）。

**2) 面试官人格 / 轮次 / 阶段切换**
- offerMaster：三档人格（peer/high_peer/manager，`backend/app/agent/prompts.py:3-26`）+ 每轮出题风格（:31-57）+ 每轮评分维度分层（:139-153）+ 三轮 `ROLE_BY_ROUND`（`api/interviews.py:20`）。纯 prompt 实现，最"细"。
- DeepInterview：sections（intro/behavioral/technical/coding/wrap）+ 原生人格交接 `CodingRoundAgent/BehavioralAgent`（`live/handoffs.py:71-86`，保留 chat_ctx）+ 3 个 avatar persona（`apps/web/components/avatar/avatar-stage.tsx`）。
- MockMate：多面试官 + 9 阶段状态机（破冰→简历→技术广度→深挖→项目拷打→压力→HR→反问→收尾，`mock_interview/interviewer_config.py:17-59`）+ 面试官切换信号（`main.py:1516-1522`）。
- AI-Interview：每轮多 panelist（`master_agent/base.py:124-142` InterviewRound HR/TECHNICAL/BEHAVIORAL + PanelData.interview_round_part_of）、LLM 决定下一位发言者（`master.py` `SpeakerDeterminationOutputMessage`）+ 逐轮 topic/subtopic 对话历史追踪（`interview_topic_tracker`）。
- ai-mock-interview：screening/professional/final 三轮 + 职级注入（`src/lib/prompts.ts:158-161`）。

**3) 现场写代码 + 面试官读到你代码**
- **Assess-AI**：编辑器代码经 LiveKit TextStream `code-update` 实时推给 agent（`frontend/app/interview/page.tsx:176-193`），agent `get_latest_code` 工具把候选人当前代码交给 LLM（`agent/agent.py:156-165`、prompt 中"CODE EDITOR RULES"）。→ 面试官实时读到你的代码。
- **grillkit**（先行结论漏掉）：Monaco 编辑器 + Judge0 真实执行（`app/coding/use_cases/run_tests.py`）+ LLM 评审"submitted code"全文（`app/coding/domain/evaluator_prompts.py:9`）。→ 面试官读到提交的代码，且代码被真实执行。
- AI-Interview 有 coding 环节（starter code + `DONE_PROBLEM_SOLVING` 消息 + 前端 `LiveCodingLayout.tsx`），但"面试官实时读码"未在代码中证实。
- DeepInterview 的 coding 轮是口头（`handoffs.py:23-28` 让候选人 think aloud），无编辑器/读码工具。

**4) 候选人视频 / 摄像头**
- AI-Interview：候选人实时摄像头（`client/src/hooks/useCameraStream.ts` getUserMedia；`components/interview/VideoParticipant.tsx` 候选人 live video + AI panelist 头像）+ 视频分块上传（`backend/routers/video_chunk.py`）。→ 群面/视频维度最强。
- socratic_mirror：候选人摄像头（rPPG 生物特征 + prompt 明示 "You can SEE the student"）。
- ai-interviewer：候选人摄像头（`index.html:325-335`）。
- Ai-Video-Interviewer："视频"是半造假——摄像头仅本地预览不上传，AI 侧是静态图片 `ai_visual.png`。
- DeepInterview：无候选人摄像头（纯语音 + 面试官侧 avatar，且 avatar 视频素材缺失时是渐变占位，`avatar-stage.tsx` 注释明确 "no real loops exist yet"）。

**5) 追问像真人**
- offerMaster：设计最"像"——追问必须引用候选人原话（`prompts.py:100-101` "你刚才提到的 X"）、跨题矛盾必追问（:94）、8-20 字衔接语 acknowledgment（:104-111）、`MAX_FOLLOWUPS=2` + 激进/平衡/宽松策略（`config.py:39-40`）。

- MockMate：追问必须引用对方刚说的话、短答(<80 字)施压、追问阶段禁换话题（`mock_engine.py:251-269`）。
- DeepInterview：每题最多 1 个轻追问 + 预置 followups + 难度建议工具（`live/interviewer.py:43-62, 170-180`）——克制型。
- Assess-AI：结构化流程内 LLM 自然追问（agent prompt 面试流程）。
- ai-mock-interview：LLM 实时生成追问（上限 2），但**下一题文本被规则锁定题库原文**（`src/lib/prompts.ts:181` "response 必须逐字使用上面的'下一题原文'"）——半造假点。

**6) 造假/名不副实核查**
- warmscreen：**确认造假**——`voice-interviewer.ts:82-105` 接话用硬编码短语数组 + `Math.random()`；analyzer/scorer/planner 全是规则（`analyzer.ts:39` "Simulate AI analysis (in real implementation, would call OpenAI/LLM)"）；全仓 agents 无任何 LLM 调用。
- socratic_mirror：**部分造假**——posture 告警是 `Math.random()`（`src/components/BiometricMonitor.tsx:68-76`），gazeDirection 硬编码 `[0,0,0]`（:151）；但心率是真实 rPPG 信号处理（extractGreenChannel→rollingMeanSubtraction→Butterworth→calculateBPM，:100-139），压力/信号质量由 HR/方差计算。→ "生物特征 Math.random()"只说对了一半。
- ai-mock-interview：下一题锁题库原文（见上）。
- Ai-Video-Interviewer："视频"=静态图；首问取对话最后一行（`app.py:91`）。
- ai-interviewer：README 宣称 Coqui TTS 实为 gTTS（`tts.py`）——文档造假。
- InterviewPal：后端 evaluation 相关三个文件为空（`services/evaluation_service.py`、`services/interview_service.py` 0 字节），面试 agent 是死代码。
- AI-agent-Avatar-Interview-Assistant：大量未接线死代码，FormRecognizer 声明未用。
- grillkit / intervio / offerMaster / DeepInterview / Assess-AI / MockMate / NextStep.AI / interview-skills：未发现实质造假（MockMate 的"打断"是文本级模拟，需如实说明）。

### 我的独立结论（任务二）

- **综合"最像真实面试"：DeepInterview**。它是唯一同时具备：真全双工可打断语音（VAD+语义断句+3 词打断门槛）+ 人格/轮次交接（coding/behavioral 原生 handoff）+ 硬性时长/轮次守卫（`guard.py` SessionGuard，默认 20 分钟/80 轮，`core/config.py:200-201`）+ 真实 STT 转录入库 + 轻量上下文 prompt（`interviewer.py:43-62` 只注入紧凑摘要+当前题）。短板：无候选人摄像头、无写码编辑器。
- **技术面（现场写码+面试官读码）：Assess-AI 与 grillkit 并列，按场景区分**。Assess-AI = 全双工语音 + 面试官实时读码（工具取当前代码），无代码执行；grillkit = 录音回合 + Judge0 真实执行 + LLM 评审提交代码全文，追问也引用原话。若强调"语音实时性"选 Assess-AI；若强调"代码真实被执行/评审"选 grillkit。**先行结论只提 Assess-AI，漏了 grillkit。**
- **人设+追问最像：offerMaster 确认**（三档人格+引用原话+衔接语+追问上限+跨题矛盾检测）；grillkit 的追问设计同级别。
- **群面/多 panelist+候选人摄像头：AI-Interview 确认**（多 panelist 逐轮+发言者决策+候选人实时摄像头+视频录制）。
- **需要补充的全双工候选**：interview-ai-assistant（LiveKit 可打断+RAG，但仓库混乱、README 夸大 Tavily）与 InterviewPal（OpenAI Realtime，但评价未完成）也是真全双工——若按"完整产品"论，仍是 DeepInterview/Assess-AI 领先。

## 三、对先行结论的逐条核查与修正清单

**(1) "信息最强：MockMate（运行时联网研究→结构化岗位画像，多引擎 bing/baidu/360，注入评分与出题）；DeepInterview（渠道最多：CV+JD+公司研究+RAG 知识库+题库包，typed InterviewContext）"**

- ✅ **确认**：MockMate 三引擎为 360/bing/baidu（`web_research.py:70-98`）；画像字段含 hiring_status/salary_range/company_insights/sources（:379-401）；**"注入评分"属实**（`main.py:888` → `interview_engine.py:843` 评估 prompt 带"岗位信息"），"注入出题"属实（`mock_engine.py:220,288`）。
