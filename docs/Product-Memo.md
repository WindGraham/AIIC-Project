## ① 目标用户与核心痛点（访谈了谁）

**访谈 11 人**：2 位面试官 + 9 位同学。

- **面试官（2位）**：一位参与过保研复试的校内老师；一位基模公司参与面试招人的技术岗员工。
- **保研复试（3位）**：两位 23 级、一位 24 级学长。
- **实习面试（6位）**：不同年级同学，3 位校内、3 位校外。

**大家的三个核心诉求：**

1. **获取信息**（最本质）：希望模拟面试能帮自己获取信息——公司内部看重什么、面试官喜欢问什么、岗位的人才画像、会更关注简历的哪个部分。"如果没有足够信息，我们的 AI 模拟面试官到底也是过家家性质。"
2. **获取经验**：这一项在前两次面试最有效，尤其是从没面过的同学——让对面试整体有详细了解，能更好地缓解焦虑。
3. **改进简历**：希望面试官问得严一点，找出简历里不足的点，改到相对完美。

> 面试官侧的关键补充：**实习面试官**（技术岗员工）看重**性格/表达**软因素，倾向按需**出情境题/压力面**，且强调"简历再光鲜也要做过对口题才能入职"；**保研面试官**（校内老师）则认为**软因素影响小**（只有特别紧张才被关注）、更偏**追问简历内容**。这印证了实习与保研两种场景差异很大。

## ② 产品设计说明

**方向选择**：聚焦**计算机行业技术岗实习面试**，保留**保研复试兼容入口**但不作为主要处理。

**原因：**
① 保研复试的同学普遍相对有把握；
② 虽题面说"学弟学妹找不到合适的学长学姐对练"，但调研显示**请教自己的学长学姐才是最有效**的方案；
③ 当前搜索能力不足以对细小的专业方向建立"委员会式群面 agent 集群"；
④ 作者本人更了解计算机行业技术岗面试流程。

**核心功能（每项对应一个痛点）：**

- **获取信息 → 岗位画像实时检索**：不只把 JD 丢给 agent，而是**尽可能查岗位信息**——传统搜索引擎之外，还接入**小红书、知乎等搜索 skill，去搜"实习面经"**，结构化出岗位画像（技能/考察点/公司流程/高频题）注入出题，让面试官 agent 掌握更多信息、也能给同学传达更多。
- **获取经验 → 让模拟面试"真实"**：结合自己多次实习面试经历，做了**预约面试 → 自测设备 → 按时进入**的完整流程来缓解紧张；面试间提供**三种模式**（文字 / 按住说话 / **全双工 tts-llm-stt 实时对话**，后者受限开发时间目前不太稳定）+ **LiveKit 视频房间**（麦克风/摄像头/屏幕共享）；coding 环节**按岗自动配题** + AI 实时读码判分给提示阶梯；**AI 看屏幕**（Gemini 视觉）。
- **改进简历 → 不同面试官风格 + 会议总结**：提供多种**面试官人格**（同级/资深同级/主管，允许选严格的），面试后根据过程生成**面试会议总结 + 反馈**（`interviewer_os`：missing_slots → what_i_want_to_hear → 一句话建议，只在报告呈现）。

## ⑤ AI 工具使用

- **LLM**：DeepSeek（OpenAI 兼容）——大脑 / 出题 / 评分 / 判码。
- **视觉**：Gemini（aixhan 中转）——AI 看屏幕。
- **语音**：Volcengine（STT，流式/一次性）+ MiniMax（TTS，流式/一次性）。
- **信息搜索**：多引擎聚合 + 牛客匿名面经 + Tavily（可选）+ **小红书/知乎真实浏览器登录态**（Playwright）。
- **开发/测试**：AI 编码 Agent + **并行 subagent 集群做对抗式审查**（前端/后端/端到端/测试），全程真实 API 联调、mock-first 降级。

**技术栈**：Next.js 16（App Router）+ FastAPI/Pydantic；LiveKit（视频，自托管 `wss://voice.windgraham.art`）；SQLite（独立数据盘 `/data/probedesk`）；题库=离线 LeetCode-CN 150 题；systemd 常驻（agent:8000 / web:3101）。

> **参考**：主要参考了 **DeepInterview** 的架构理念（**prep→live→post**）。
