## 0. 一句话定位（先想清楚我们到底做什么）

> **不是"AI 出一道题把你面一遍"，而是一个"模拟真实面试的面试房间平台"。** 学生预约一场含企业/岗位/时间的面试，到点进入 Room 与 AI 面试官进行**音视频/共享屏幕/手撕代码**的真实面试，结束后拿到**可转发的实录/文字稿 + 结构化面试报告 + 「面试官脑回路」**，让"从没面过试的人"完整走一遍、并得到比直用 ChatGPT 更可执行的反馈。

**"AI 面试官" vs "AI 面试" 的区别**（你强调的）：
- "AI 面试"＝它的**音视频/编码**能力是全部；
- "AI 面试官"＝它是一个**有角色、有意图、会深挖、有脑回路**的**面试官**，平台提供**真实场景**（入场、设备测试、手撕代码、投屏、复盘、发链接让人评）。我们做后者。

## 3. 聚焦边界（做窄做深，符合挑战"别做太泛"）

- **主场景**：`计算机 · 算法/研发岗` 的实习/校招面试。
- **其他暂时不做**：非技术岗、产品/运营、群面。
- **保研复试**：**保留在预约里作为选项**，但**不优先实现**。原因：保研复试本质是"多面试官 + 半结构化学术面"，模拟效果差；真正要模拟的是**多面试官 panel**（§3.1）。故 `book` 里保留该选项，报错/占位"规划中"。
- **刻意识别的边界（写进 Memo 的"刻意不做"）**：真人语音全双工极限体验、数字人头像、账号/支付、屏幕实时 AI 语义理解（首版只做"读码 + 读屏事件"，不做强语义）。

### 3.1 保研复试 = 多面试官 panel（不优先）
- 设计上预留：Room 支持 `interviewer set`（≥1 个 agent，可多 persona 同时在线扮演"导师团"）。
- 但因复杂度高、效果难保证，**本期不实现**；在需求文档里写成 P1/P2，避免超时。

## 4. 面试房间（Room）——核心

> 参考 DeepInterview 的 prep→live→post 三段 + LiveKit 能力 + 你 ProjectProbe 的"脑回路/槽位"。

进入 Room（**可提前**，但 agent 不随用户进）后至少包含：
1. **语音对话**（AI 面试官开口；全双工/流式，见 §6 双工流）。
2. **视频对话**（候选人摄像头；agent 侧可视或仅语音，见 §6）。
3. **共享屏幕**——**且要求 AI 有"读视频流"的能力**（agent 能**看**候选人共享的屏幕）。
4. **题目 + 可写代码的编辑器**——候选人收到一道题 + 一个代码编辑器；**agent 能实时看到该 editor（读到候选人当前代码）**。
5. （时间到/流程结束）→ 结束会 → 触发 post 流程（§5）。

> LiveKit 说明：Room 用 **LiveKit 原生能力（音视频、共享屏、track/subscription）**；前端**以 LiveKit Meet 为基础但替换/移除其会议特征**（去掉"大厅/参会者列表/举手/聊天"等会议元素，改成"面试"沉浸式布局：题目 + 编辑器 + 面试官 + 你的投屏/摄像头）。

---

## 5. 面试后交付物（Post）

1. **实时转写（transcript）**——面试过程中与 AI 的对话逐句转写（DeepInterview `wire_transcript_capture` + 字幕，或 LiveKit 的 transcript/STT 事件）。
2. **实时录制（recording）**——面试过程**录制视频**（LiveKit egress 录制)。
3. **可转发链接**——**文字稿 + 录制视频**都有公开转发链接（发给别人帮评）。→ 需要一个"分享/查看页"（公开、可只读匿名）。
4. **结构化面试报告**——总分/关键证据/最危险追问/手撕代码表现/`interviewer_os` 脑回路（§6.4）/简历改写/下一步训练计划（复用 ProjectProbe 的报告结构 + DeepInterview 的评分）。
5. **面试官"思考流程"**（你强调的点）——**只在面试后总结里展示**，**面试过程中不实时展示**。

## 6. 技术架构（LiveKit + agent + 三个领域）

> 你已定调：**底层用 LiveKit + LiveKit Meet 前端为基地，替换部分元素**；过程用 **DeepInterview 方案**；我们补三块。

### 6.1 技术分层（四大块）
1. **LiveKit 基础能力**（transport）：Room、音视频 track、共享屏 track、录制(egress)、转写。复用 LiveKit Meet 前端骨架。
2. **实时写代码组件**：Room 里的 Monaco（或 CodeMirror）编辑器 + 协同/同步到 agent。参考 `interview_platform1`（Yjs+MonacoBinding）或 DeepInterview 的轻量做法；agent 侧用 function tool 读当前代码（→ 手撕代码题）。
3. **Agent 侧级联（cascade）实现**：DeepInterview 思路 `STT→LLM→TTS` + `InterviewContext`(prep出来的候选/岗位/gap/计划) + 人格/阶段切换 + 槽位/脑回路。**这就是"AI 面试官"的"人"**。
4. **"看共享屏幕"能力**：agent 能**接收并理解**共享屏。方案：LiveKit 把屏幕 track 帧送 agent，agent 用**视觉模型**（多模态 LLM，如 Gemini/Qwen-VL）**定期抽帧**做"屏幕理解"，产出"面试官看到的画面注释"。首版可做**低频抽帧 + 事件化**（如"现在屏幕上在写 X"），不做实时全帧语义。

### 6.2 双工流（full-duplex）如何实现
- 参考 DeepInterview `worker.py`：LiveKit `AgentSession` + Silero VAD + `turn_detection(MultilingualModel)` + `interruption: {min_words:3}` + 流式 STT partials + RTC 双向音频。全双工 = 麦克风持续流进 agent，agent 持续说话，靠 VAD/语义端点/打断门控切换。
- 关键点：**级联不是"录完再转写"**，而是**一路流式**；否则无法打断。

### 6.3 agent 看共享视频流的方案
- 见 §6.1.4。落地三步：① LiveKit 订阅 candidates track → 抽帧（如每秒 1 帧）；② 视觉 LLM 对该帧打注释（结构化 JSON）；③ 注释注入 `InterviewContext`/当前轮 prompt。首版做"抽帧 + 多模态打标"，P2 再升级"流式语义"。

### 6.4 面试官"思考流程"复用（承袭 ProjectProbe）
- 沿用 `interviewer_os` 结构：`hidden_concern / why_this_question / missing_slots / what_i_want_to_hear / risk_level`。
- **仅 post 展示**（报告/复盘），不实时展示。prompt 里同样约束"这是面向用户的判断摘要，不是 chain-of-thought"。
- 可再叠加"面试官观看屏幕/代码时的思考"（如"我在注意你代码里的 X"）。

## 7. 信息获取（AI 模拟面试官的本质缺陷的解）

我们解决的是"**信息**"不足：AI 面试官不该只是"知道岗位 JD"，而应**掌握大量关于该岗位/该企业的真实信息**，从而问得准、评得真。方案三层：

1. **运行时联网研究（岗位/企业情报）**：对用户给的公司+岗位，**多引擎搜索**（保留 DeepInterview 的搜索适配器 + MockMate 的 `web_research` 多引擎/公司定向）+ 社区面经。
2. **社区/社媒检索（MCP / skill 接入）**：接入开源 MCP/skill（小红书 `xhs-mcp`、知乎 `zhihu-mcp`、`Stride28-search-mcp`、LinkedIn `linkedin-spider` 等），拉取"XX 公司 XX 岗 面经"。**优先用现成开源工具（省时）**；若某平台无稳定开源工具（如脉脉），则我们实现轻量 wrapper 或降级到搜索引擎 + 站内聚合。
3. **题库/力扣**：`neetcode/leetcode_datasource` 可拿到结构化题目（题目/难度/编号/URL）；拟自建一个"标签→题"的映射缓存（本地 JSON + 定时刷新），**支持根据岗位拉对应 tag 的题**作为手撕代码题源。注意**力扣反爬/条款**：优先用公开数据集/开源 mirror，避免违规。

**整合方式（信息 → prompt）**：**不直接把生搜索串喂给 LLM**，而是**中间接一层 agent（Researcher/情报整理 agent）**先检索、去噪、**结构化**成"岗位画像/考察图谱/面经要点/公司风格"（JSON），再注入。参考 MockMate `web_research.py` 的"结构化画像对象 + 缓存 90 天"、ProjectProbe 的"secret 知识/标准模板"。→ 既省 token 又提升质量与可解释性。

## 8. 面试官 prompt 怎么构建（组成）

一个完整的"AI 面试官系统 prompt"应包含（分层）：
1. **人设/人格**（persona）：岗位对应级别（peer 同级 / high-peer 资深 / manager 主管）、语言风格、压迫感强度、（保研）导师团若启用则多 persona。
2. **面试流程/阶段**：状态机（DeepInterview sections / ProjectProbe S1-S6 项目深挖 / 通用 HR→技术→手撕→反问）。
3. **槽位/考察点**（REQUIRED_SLOTS + 每阶段 what_i_want_to_hear）：决定"该深挖什么、推进到什么程度"。
4. **注入的岗位/企业信息**：**经 Researcher 整理后的结构化画像**（§7）——不是裸文本。
5. **候选人信息**：简历解析出的 CandidateProfile + 项目深挖要点（deep interview CV 解析 / 参考 ProjectProbe 的 S1-S6 深挖）。
6. **追问/脑回路约束**：interviewer_os 输出规范（隐藏担忧/为何追问/缺失槽位/期望听到/风险等级），且限定"面向用户摘要"。
7. **评分体系**：rubric + 逐维度 + 证据引用 + 手撕代码/共享屏表现。
8. **注入方式**：**结构化情报 + 类目权重**（参考 interview-copilot 的"评分标准类目加权"）而非堆原文。

## 9. 挑战文档逐条对照（含"你没注意到/要补齐"的点）

对照 `2026-08-30_项目挑战说明(1).pdf`：

- **评分核心句**："应让评委感受到，**相比直接使用 ChatGPT，这个产品真的能更好的帮学生准备面试**。" → 我们的差异化载体 = ①**完整真实场景**（入场/设备测/手撕码/投屏/复盘/分享）②**信息充沛**（岗位/企业情报+面经）③**可执行反馈 + 面试官脑回路**。这三条要在 demo 与 Memo 里讲清。

- **语音/视频是加分项，不是必选项**：文档明说"文字做扎实是基础线"。→ **warning**：16h 内 Voice+Video+Code+Screen 一起上风险高。**建议 MVP 保证"文字/语音闭环 + 出题 + 评分 + 脑回路 + 转写/录制/分享 + 报告"这条线真正跑通**，Voice/Video/Shared-Screen/Code 做成"有交互但内核基于同一套状态机"的增强层。
- **务必标注自写/AI/fork**：我们 **fork LiveKit Meet + 复用 DeepInterview 思路** → README/Memo 必须写明 fork 来源与实质性改动（这是"公平与诚信"要求，也是低分信号规避）。
- **Demo 前 30 秒 wow moment**：建议首屏 = "预约一场 XX 岗位面试 → 进 Room 开口 →（速览）→ 结束后看**面试官脑回路 + 逐题报告 + 可转发实录**"，把"真实 + 脑回路"当 wow。

## 10. 架构拆分 & 开发流程拆分（满足"多次 commit"）

按**垂直切片**交付，每片都是"能跑、可测、可 demo"的增量（配合"提交时间戳"与"commit 频繁"要求，避免最后一次性提交）：
