# 开发计划 · ProbeDesk 剩余任务（把你列的"全部补进去" + 三个 research 亮点）

> 原则：每阶段 = **可演示 + 真实 API 测试 + 对抗性审查 + 独立 commit**；聚焦 `CS 算法/研发岗`；保研复试只留入口（多面试官 panel 不优先，但保留场景字段）。目标：**完美视频 + 完整平台**。

---

## Phase A — 平台外壳（先立"平台感"，最影响视频）
| 步骤 | 内容 | 状态 |
|---|---|---|
| **A1 后端调度 / 持久化** | bookings/interviews 落 JSON store（`data/store.json`）；`POST /api/interviews/book`（完整字段：简历/公司/岗位/JD/时间/补充信息/是否手撕/场景含保研）、`GET /api/interviews`（状态+`seconds_until_start` 倒计时）、`POST /api/interviews/{id}/start`（到点/手动开始 → build_plan → room） | ✅ **已写并测通**（book→list 倒计时→start 返回计划） |
| **A2 管理简历页** | 多份简历 CRUD、设默认、粘贴/上传、技能画像抽取；简历列表存 store | 🔲 |
| **A3 功能测试页** | 用户自测麦克风/摄像头/屏幕共享/投屏，**不接面试官**；本地电平表 + 录一段本地回放（getUserMedia + MediaRecorder，无需 agent） | 🔲 |
| **A4 面试列表页** | 显示所有面试：岗位/企业/时间/**距开始还剩多久**、状态（待开始/可进入/进行中/已结束）；进入/开始按钮 → room；倒计时 client `setInterval` | 🔲 |
| **A5 预约表单补字段 + 时间调度** | 选简历/预约时间/补充信息/是否含手撕代码/场景（实习|保研）；"可提前进入、**AI 到点才进**"（scheduled_at 到点才生成 context / 标"可进入"，或手动"开始"触发 agent 加入） | 🔲 |

> A 完成后视频主线可拍：**预约 → (选简历/时间/是否手撕) → 列表倒计时 → 进房(可早进/AI晚进) → 面试(语音/手撕码/看屏) → 报告 → 分享**。

## Phase B — 媒体增强（真实感，视频加分）
| 步骤 | 内容 |
|---|---|
| **B1 视频对话** | 候选人摄像头 track（LiveKit `VideoTrack`），agent 侧可视（或至少 candidate 自看 + 面试官头像） |
| **B2 实时共享屏幕 + AI 实时读** | 从"截帧上传"升级为 **LiveKit 屏幕 track + 按帧送视觉模型**（低频抽帧打标，"面试官看到：屏幕正在写 X"）；复用现有 Gemini 视觉 |
| **B3 实时语音字幕** | 与 AI 对话的**实时转写字幕**（STT partial → `useTranscriptions`/agent 事件 → 字幕面板） |
| **B4 实时录制视频 + 录制转发链接** | LiveKit egress 录 RoomComposite → 视频 + 转发链接（`/share` 已支持文字稿；补视频） |

---

## Phase C — 差异化放大器（你强调的三个 research 亮点）⭐
| 步骤 | 内容 | 来源 |
|---|---|---|
| **C1 人格分层** | peer(同级)/high-peer(资深)/manager(主管) 三档 **面试官语气/压迫程度/出题风格**；预约或岗位级别自动选档 | offerMaster |
| **C2 跨场记忆 / 学习曲线** | **多场趋势 + 薄弱项重练 + 进步曲线**：跨场记录每个 `competency`/`missing_slot`，下一场 prompt 注入"上次薄弱点"，报告页显示多场趋势 + 重练入口 | warmscreen / intervio / MockMate |
| **C3 按岗位自动配题** | job.tech_stack/岗位 → 算法 tag → **题库选题**（150 题），把"本场手撕题 × 题源 × 难度"**显示在职位/预约里**，并注入 coding 轮 | neetcode datasource / doocs |

> C 是"比 ChatGPT 更好"的最强论据：**它不仅单场反馈，还跨场帮你构建进步曲线、并按岗位配题**。

| 步骤 | 内容 |
|---|---|
| **D1 systemd 持久化** | 把 agent/web 装成 systemd（`deploy/*.service`），开机/后台常驻，代码更新后重启 |

## 执行顺序（依赖 + 风险）
- **先 A（平台外壳）→ 再 C（差异化，研究亮点）→ 再 B（媒体）→ D（运维/提交收尾）**。
  - 理由：A 让"平台/完整流程"成立（视频必拍）；C 是**评委最看重的"比 ChatGPT 好"的实证**（跨场进步曲线 + 按岗配题 + 人格）；B 中的视频/实时字幕是**加分非必需**，放 C 后避免占主线；D 收尾。
- **保研复试**：保留预约"场景=保研复试"选项 + 计划里留 `interviewer set`（多面试官）占位，**实现不优先**。

## 风险 / 取舍
- **视频/实时字幕**（B）依赖 LiveKit track + egress，工作量大；若时间紧，**视频主线以 A+C 为核心**，B 做"有交互但稳定"。
- **跨场记忆**（C2）需要一个跨场存储（复用 `data/store.json` 或 Supabase）；做"本机可复现"即可，不追求登录/账号。
- 每阶段 `git add` 前**审计无 key**；`data/store.json`/`.cache`/`researcher_cache.json` 已 gitignore。
