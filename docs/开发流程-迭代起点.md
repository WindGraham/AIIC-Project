> **主文档**。是 5 个调研 subagent（LiveKit组件 / prompt构建 / 信息搜索 / 实时语音双工 / 前端）＋ 测试数据"双 agent 互聊"方案的汇总，全部给出仓库内"借码"路径。

> **配套文档**：`API与密钥清单.md`（要你提供的全部凭据）· `产品方案-设计分析.md`（产品/模块/评审对照；**其状态机口径以本文件为准**——我们走"计划+游标+记分卡、无硬状态机"，DeepInterview 式）。
>
> ⚠️ 口径声明：本文件顶替早期"偏硬状态机"的设计稿。所有"状态机"字样解读为 **计划(plan)+游标(cursor)+记分卡(scorecard)**；ProjectProbe（`research/reference/Fomalhaut-AIIC-Project`）是**学长 Fomalhaut647（2026 年 5 月）**的作品，我们只借鉴其 `interviewer_os`/槽位/反馈纪律与 commit 拆分，**不是我们的项目**。

## 0. 一句话总决策

**先做"面试官大脑"的纯文本闭环（prep→live→post）＋ 双 agent 互聊测试 harness ＋ 离线题库（零第三方 key、最快验证差异化、顺手产出 demo 转写与报告），再往上盖语音外壳（LiveKit 全双工）、平台前端（Next.js 房间）、手撕代码、录制分享。**

语音与前端都是"外壳"，**core 是那段可被纯文本驱动、可回归测试的"大脑"**。

---

## 1. 统一架构（五块 + 测试）

### 1.1 分层原则：大脑 vs 外壳（最关键）
把"面试官大脑"（读计划出下一问、出题、追问、更新记分卡、判手撕代码、事后出 missing→想听什么）做成**纯 LLM 文本循环**，与"语音外壳"（LiveKit + STT + TTS I/O）**隔开一个文件边界**。DeepInterview 就这么分层（`live/interviewer.py`=大脑，`worker.py`=语音壳）。好处：
- 大脑**无 key 可测**（DeepInterview `core/config.py` 默认离线、`core/adapters/mock.py`）。
- **双 agent 互聊**直接驱动大脑 → 测试数据 / 回归语料 / demo 转写与报告。
- 语音只是 I/O 包装，工具契约稳定后随时往上接，demo 当天 key 挂可降级 PTT/文字。

### 1.2 各块方案（一句话 + 借谁）
- **① LiveKit + 组件**：选 **b（`@livekit/components-react` 自建前端）+ c（Python `livekit-agents` 参与者）**，**不 fork livekit-meet 整站**（会议语义太重），只借 `/tmp/livekit-meet` 的 `connection-details`/`record/start`/`record/stop` 三个路由。**关键改动**：给 `WorkerOptions` 加 `agent_name` + 后端开面时 `agent_dispatch.create_dispatch`（否则一进房 worker 就接 job，不满足"提前进房 AI 不在"）。抄 DeepInterview `worker.py` + `/tmp/livekit-meet` 三路由。
- **② prompt 构建**：照 DeepInterview prep→live→post + "黑色板 `InterviewContext`"（candidate/job/company/gap/plan/cursor/answers/scorecard）。live 只放**精简 prompt**（候选 compact 摘要 + 当前题 + 语言 + 少量人格），每轮重刷当前题；工具 `get_next_question`/`next_section`/`save_answer`/`suggest_difficulty`/`request_clarification`/`end_interview`/`start_coding_round`/`start_behavioral_round`；persona 交接用**继承式子 Agent + chat_ctx 延续**（`live/handoffs.py`）；脑回路**只进 post**。抄 DeepInterview `live/*` + `prep/*` + `post/*` + `shared_models.py`，ProjectProbe 借 `REQUIRED_SLOTS`/`InterviewerOS`/严格 JSON 指令。
- **③ 信息搜索**：做 **Researcher 中间层**。底座 **MockMate 三引擎 HTML 聚合（360/bing/baidu，零 key，约 450 行）** + **牛客匿名面经 API** + **Tavily keyless**；产物 **结构化 `JobProfile` JSON**（required_skills/tech_stack/interview_focus/likely_questions/coding_tendency/company_profile/sources/missing_company_info），注入 `question_planner` 而非喂原文；90 天缓存 + `fallback_profile` 兜底。**小红书 / 知乎 = 真实接入（不作为可选项）**：做成 Researher 层里的 **provider**，用官方 MCP server（xhs-mcp / zhihu-mcp-server，交给它们处理签名逆向）+ env 注入 cookie（`XHS_COOKIE` / `ZHIHU_D_COOKIE`）+ **优雅降级**（无 cookie / 签名失效 / 风控 → 该 provider 返回"暂不可用"，自动跳过，绝不 crash 主线）+ **90 天缓存**（cookie 当天过期也有上次结果可用）。脉脉（无稳定开源）/LinkedIn（法律）=**不做**。抄 MockMate `web_research.py` + 面经猎手 `scrape_nowcoder.py` + DeepInterview `search.py`/`skills/`/`interview-skills references/`。
- **④ 实时语音双工**：**主路径全双工级联**（Deepgram nova-2 zh 先稳定版再冒烟 nova-3 zh + ElevenLabs Flash zh + Silero VAD 预热 + MultilingualModel + `interruption:{min_words:3, min_duration:0.6}` + endpointing{min 1.2, max 4.0} + preemptive generation）。**PTT 降级**（manual 模式 3 个 RPC + `STT_PROVIDER=whisper` 环境开关）＋ **text 兜底** 三级保险。录制走本机 **egress v1.8.0**（已在跑）。抄 DeepInterview `worker.py` 的 `build_stt/build_tts/build_vad/build_turn_handling`。
- **⑤ 平台前端**：Next.js 16（App Router）+ `@livekit/components-react` + Tailwind 4 + zod + zustand（仅房间态）。路由：`home / resumes / booking / interviews / test-room / room/[id] / report/[id] / share/[id]`。状态用 **Supabase 或 agent API（FastAPI）内存 repo**（二选一）；`web` 经 Next route handler 代理 `agent`，`AGENT_API_URL` 不出浏览器；Next 15/16 `params` 是 Promise 需 await。抄 DeepInterview `apps/web/*`。

### 1.3 手撕代码编辑器（让 agent 看到代码）
Monaco（`ssr:false`，loader 离线自托管）→ onChange **2s 防抖** → `sendText(code,{topic:"code-update"})` → agent `register_text_stream_handler` **只存快照** → agent 用工具 `get_latest_code()` **按需读**（别每次注入 LLM context，会 token 爆炸且打断语音）。判对错：agent 用 `run_tests` 调 **Piston**（经 `/api/run` 代理，避免 CORS/密钥）→ 结果回 LLM 做提示 → `save_coding_result` 写进 scorecard。出题用**离线题库**（`leetcode.cn/api/problems/all/` 一次性导出 + GraphQL 取题面，精选 100–150 题落成 `data/problems.json`，已实测该 API 返回 4429 题）。**不需要 Yjs/CRDT**（agent 只读单向流足够）。抄 Assess-AI `frontend/app/interview/page.tsx` + `agent/agent.py`。

## 2. 测试数据与双 agent 互聊（重点）

**目标**：文本性能测试用**候选人 agent ↔ 面试官 brain** 互聊，纯 LLM、无语音、可复现、可回归。

- **候选人 agent**：输入画像（简历/JD/公司/岗位/职级/水平 强中弱 / 回答风格 简洁啰嗦含糊 / 会不会被带偏）→ 生成回答。这是**测试数据生成器**。
- **面试官 brain** ＝ 我们的真 agent（prep→live→post）。
- **Judge**：另一个 LLM 或规则，量化：覆盖度、防飘、难度自适应、追问深度、反馈可执行（missing_slots→what_i_want_to_hear 是否具体）、是否照计划走。
- **测试集**：小型语料库（真实感简历 + JD + 公司/岗位）配百变候选人 profile → 跑一遍 → 存**回归语料**（转写+记分卡+报告）；之后改 prompt/逻辑，重跑同批对比即可量化退步。
- **一鱼三吃**：① 验证差异化（信息充分 / 反馈可执行 / 防飘）② 无 key 开发调优回归 ③ 直接产出 demo/memo 需要的"一场真实模拟面试"转写 + 脑回路报告。
- **前提**：一个可用 LLM（DeepSeek / OpenAI 兼容，ProjectProbe 已在用）。

## 4. 迭代起点 ⭐ 从 Phase 1 开始

- **为什么 brain 先行**：零第三方 key（只用一个 LLM）、最快验证差异化（信息充分/反馈可执行/防飘）、顺手产出测试数据 + demo 转写/报告、工具契约稳定后语音/前端向上盖很干净、也是 16h 里风险最高最该先做扎实的部分。
- **配套**：**day-1 就建立双 agent 互聊 harness + 回归语料**，边开发边跑，改一点就重跑同批对比（这就是"文本性能测试"的载体）。
- **前提**：一个可用 LLM key（DeepSeek/OpenAI 兼容）/ 现有 LLM。
- **若更想先看到"网站+语音"**：可把 Phase 2 Web 壳提前到 Phase 1 之前（只做 booking→room→text 兜底），但会延后差异化验证；**建议仍是 Phase 1 先行**，Web 壳紧随其后即可见完整界面。

## 5. 风险与应对

- **语音 key**（Deepgram/ElevenLabs/LLM）：全双工为主形态，demo 当天 key 挂 → **PTT/文字兜底**，代码与报告链路不受影响。
- **中文语音精度**：Deepgram nova-2 zh 是 DeepInterview 已验证路径；**首小时冒烟 nova-3 zh**，不行就锁 nova-2。
- **信息搜索反爬**：≤10 查询/预约、UA 轮换、超时降级；**小红书/知乎作为 provider 接入，但有 cookie 才抓、任何失败自动降级（不阻塞主线）**；脉脉/LinkedIn 不做。
- **小红书/知乎 cookie 依赖**：这两个平台必须真实登录态才能抓。让用户用浏览器插件版（如 x-mcp 零部署登录）或手动 env 注入 cookie；cookie 过期时干净降级，不报错给候选人。
- **16h 内别碰**：真 LightRAG sidecar、自动判题执行器(Yjs/CRDT)、多面试官面板、实时屏幕语义、重练模式（留 schema 占位）。
