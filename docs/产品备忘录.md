## 一句话
**我们做的不是"AI 答题"，而是"AI 面试官"——一个真实、完整、有针对性的模拟面试平台**：学员预约一次针对某公司/某岗位的面试，进入真实面试间（语音对话 / 手撕代码 / 共享屏幕），AI 面试官实时提问、追问、打分，结束后给一份**可执行的评价报告**（缺了哪些点、面试官想听到什么、下一步怎么练），且**全程转写 + 分享链接 + 语音回顾**。

## 洞察：市面 AI 模拟面试缺三件事
1. **流程不完整**：大多是一次性"问答→打分"，没有从预约、简历、真实面试场景到报告、转写、分享的完整闭环。
2. **信息不充分**：AI 只会问通用题，不知道目标公司/岗位**到底怎么考、考什么**（这是 AI 面试官最大的短板）。
3. **反馈不可执行**：只给一个总分，不给"你到底缺什么、我想听到什么、该怎么练"。

我们把这三点在一个平台上解决。

## 做了什么（交付物）
- **预约 → 面试计划**：填简历 + 岗位 JD + 目标公司 → 生成**完整、针对性**的面试计划（自我介绍→项目→技术→**手撕代码**→反问，难度 1→5 递进）。
- **真实面试间**：`语音`（按住说话，实时 STT→大脑→TTS 回放）+ `手撕代码`（本地题库出题，**AI 实时读码判分**并给提示阶梯）+ `让 AI 看我的屏幕`（Gemini 视觉理解共享画面）。
- **信息充分**：Researcher 层在预约时检索（多引擎 + 牛客面经 + Tavily + 小红书/知乎[可选]）→ 结构化**岗位画像**（技能 / 考察点 / 公司面试流程 / 高频题），注入出题，问得"像真的懂这家公司"。
- **可执行反馈**：`interviewer_os` 在报告里给 `missing_slots → what_i_want_to_hear → 一句话建议`（带候选人原话证据）；**面试中不实时展示**（保留"面试官大脑"的神秘感与公正）。
- **转写 / 分享 / 录制**：问答转写可下载；**公开只读分享页** `/share/{id}` 可转发给他人评价；**语音回顾**把报告核心合成音频（录制）。

## 技术架构
Next.js 16（App Router）+ FastAPI + Pydantic；LLM=DeepSeek（OpenAI 兼容），视觉=Gemini（aixhan），STT=Volcengine，TTS=MiniMax；信息搜索=多引擎聚合+牛客+Tavily；题库=离线 LeetCode-CN 150 题（不做运行时抓取）。面试过程借鉴 DeepInterview 的 **prep→live→post**，用**计划+游标+记分卡（无硬状态机）**驱动；反馈内核参考学长 ProjectProbe 的 `interviewer_os`。

## 差异化
| 别人 | 我们 |
|---|---|
| 填空式问答 | 完整真实场景（预约→真实面试间→报告/分享） |
| 通用模板题 | Researcher 注入岗位画像，问得准 |
| 只给总分 | `missing_slots → what_i_want_to_hear` 可执行，带证据 |
| AI 不看代码/屏幕 | AI 读码判分（提示阶梯）+ Gemini 读屏 |
| 无沉淀 | 转写 + 分享 + 语音回顾 + 多场景可复用 |

## 验证
- 全部能力用**真实 API** 跑通（DeepSeek / Gemini 视觉 / Volcengine STT / MiniMax TTS），TTS→STT 回环逐字一致。
- **双 agent 自玩测试 harness**：候选人 agent ↔ 面试官 brain 纯文本互聊，量化覆盖/防飘/追问/反馈可执行；实测 strong 考生 92 分 vs weak 75 分（分数能拉开、反馈具体）。
- 边界回归（未知 id→404、畸形输入不崩）全部通过；15+ 干净 commit。
- 自研 vs fork：产品主体自研；参考 DeepInterview（架构）与学长 ProjectProbe（反馈内核），已在 README 注明。
